# 多智能体项目选题协作协议 v0.4

用途：为一个长期金融科技**项目**选题与论证。参与者分工明确，靠标准化的任务包和台账交接。

**产出是项目，不是论文。** 最终交付的是一个持续迭代的系统或产品：代码仓库、能演示的版本、明确的使用者、使用效果的记录。不以发表为目标，不为选题做系统性文献综述。论文只有两个用处：确认一个问题真实存在，或者借用一个方法。
状态：试行。每轮结束后按实际运行情况修订，修订记录见第 9 节。

---

## 1. 角色分工

| 角色 | 由谁担任 | 负责什么 | 不负责什么 |
|---|---|---|---|
| **项目负责人** | 你 | 最终决定；确认每阶段的标准；在智能体之间传递任务包和结果；联系真人；需要登录或付费的操作 | 不需要自己做检索和编码 |
| **主持与审稿** | Claude | 设计流程与标准；头脑风暴提出假设和候选；拆分任务包；审核每份结果并指出缺口；在证据基础上提出排序建议；维护台账和仓库 | 不做大规模检索（只抽查核实）；不替你做最终决定 |
| **文献与情报** | GPT | 国内外检索：机构的实际应用、现有产品与开源项目、公开数据与接口、监管文件；论文只在需要确认问题或借方法时查；读原文；按台账格式交来源 | **不排序、不推荐项目**，只交地图、证据和观察到的空白 |
| **实证与验证** | WorkBuddy（DeepSeek 驱动，在你的电脑上） | 国内网站与数据实测；国内资料的批量枚举（公告清单、赛题、岗位描述等）；数据获取、清洗、复算；小规模试验；跑代码并保存原始输出 | 不判断题目值不值得做；不改标准 |
| **外部审稿** | 一位金融科技方向的老师或从业者（待找） | 在关键阶段门槛处看一页纸材料 | 不参与日常工作 |

搜索的人不排序，测试的人不选题，审稿的人必须引用证据编号。这样每个环节都有人检查上一环节，避免"谁提出的方向就围绕谁找证据"。

## 2. 阶段与门槛

不设天数，只设门槛。

| 阶段 | 目标 | 主要执行 | 门槛（全部满足才进入下一阶段） |
|---|---|---|---|
| **P0 建系统** | 协议、基线、模板、标准确认 | Claude、你 | 你确认第 3、4 节 |
| **P1 现状地图** | 金融科技各领域现在在做什么 | GPT 为主；WorkBuddy 并行整理国内一手材料 | 每个领域都有：机构的实际应用、现有产品或开源项目及其不足、可用的数据或接口；另有岗位与赛题的需求清单；Claude 审核后无重大缺口 |
| **P2 候选生成** | 从地图中提出候选项目 | Claude 头脑风暴；GPT 补充反例 | 至少 15 张候选卡，覆盖至少 5 个领域；每张卡写明使用者、最小可用版本、推翻条件 |
| **P3 证据深挖** | 对前 5 名做深入检索和数据可行性实测 | GPT 深挖竞品与开源项目；WorkBuddy 实测数据 | 每个候选都有：最强对手清单、数据实测记录、强通用 AI 直接回答的对照结果 |
| **P4 原型** | 对前 2 到 3 名各做一个最小原型 | 你和 WorkBuddy 写代码；Claude 设计与审核 | 原型能跑，结果可复算；通过盲审（第 6 节）；至少一位目标使用者或业内人士看过演示 |
| **P5 立项** | 选定项目，写项目章程 | 你决定 | 章程包含：使用者与要解决的问题、最小可用版本范围、技术方案、数据管道、评估指标（含与强通用 AI 的对比）、版本里程碑、推翻条件 |

每个阶段内部可以多轮。每轮结束时 Claude 写审核意见：哪些结论有证据、哪些缺、下一轮任务包是什么。

## 3. 金融科技的范围（广义）

**定义**：科技赋能金融。用数据、算法、人工智能、软件系统或网络基础设施，改变金融服务的提供方式、金融决策的做出方式、金融风险的识别与管理方式，或者金融市场与监管的运行方式。

**包括但不限于**：

- 传统金融科技领域：支付清算、数字信贷与风控、财富科技与智能投顾、保险科技、监管科技与合规、数据要素与隐私计算、资产数字化；
- **AI × 金融**：机器学习、大模型、智能体用于任何真实的金融问题，包括定价、风险、流动性、现金流、资产配置、信用、保险、公司金融、家庭金融决策、金融市场测量与监管；
- 与"金融五篇大文章"（科技、绿色、普惠、养老、数字金融）相关的技术应用。

**判定方法：双删检验**

- 去掉技术部分，项目还成立吗？成立 → 不算金融科技，是纯金融或商学课题。
- 去掉金融部分，项目还成立吗？成立 → 不算金融科技，是纯技术或运营课题。
- 两次都不成立，才在范围内。

**排除**：以 A 股选股或交易策略收益为主要产出的项目（与 perquant 重叠，按你的要求）。

## 4. 候选评价标准（P2 起使用）

### 4.1 硬门槛

| 编号 | 门槛 |
|---|---|
| H1 | 通过第 3 节的双删检验 |
| H2 | 有具名的使用者（个人、小商户或机构里的具体岗位），面对重复或高价值的金融决策 |
| H3 | 结果能用客观数据检验，并能公平地和"直接问强通用 AI"比较 |
| H4 | 不属于否决类型：投顾体检、审计或事实核验、静态计算器、普通荐股、比价、报告生成 |
| H5 | 数据能获取、重建、模拟或代理（付费和申请都算） |

### 4.2 打分维度（1 到 5 分）

| 维度 | 含义 |
|---|---|
| 技术与金融的结合深度 | 技术是否改变了金融决策或服务的做法，而不只是做分析展示 |
| 前沿性 | 是否对应大机构当前的实际投入、监管与规划方向，或近两年的前沿研究 |
| 空位 | 个人能做出什么大机构没做、或做了没公开的东西 |
| 抗模型进步 | 下一代模型更强之后是否仍有意义 |
| 长期可扩展 | 能否持续迭代一年以上，功能、用户、数据能不断扩展 |
| 可做性 | 你借助 AI，几个月内能否做出能跑、能演示的版本 |
| 面试价值 | 实习和工作面试时讲得清、演示得出：做了什么、给谁用、效果如何；对广泛的金融科技岗位都讲得通，能体现金融科技学生身份 |

**评分纪律**：
- 总分由脚本或表格重算，不信任任何人报的合计；
- 头两轮评分后检查分布：都在高分段说明标准太松，都过不了中位说明标准太紧或候选太窄。

## 5. 交接物与仓库结构

所有交接物放在本仓库。

```
00_协议/     本协议
01_基线/     项目基线：不能被悄悄改动的约束和事实
02_任务包/   每次分派的任务包
03_返回/     GPT 和 WorkBuddy 交回的原始结果（原样保存，不修改）
04_审核/     Claude 每轮的审核意见
05_台账/     来源台账、主张台账、决策日志
06_候选卡/   P2 起的候选
07_参考/     外部方法参考
```

### 5.1 任务包（交接三件套）

每个任务包必须自成一体，不依赖对话中的隐含上下文：

```
任务包编号：P1-R1-GPT
发给：
目标：一句话
背景摘要：只给完成任务必需的信息（避免锚定）
输入材料：附件或链接
要做的事：按优先级 P0 / P1 / P2
不要做的事：
不要改动的：
交付格式：
完成标准：
```

### 5.2 来源台账

| 字段 | 说明 |
|---|---|
| 编号 | S-0001 起 |
| 标题、作者或机构、日期、链接 | |
| 类型 | 产品页、开源项目、数据集或接口文档、监管文件、机构报告、赛题、岗位描述、论文、新闻 |
| 阅读程度 | L0 只见标题；L1 读摘要或二手转述；L2 读了正文；L3 数据或结果已复现 |
| 支持什么判断 | 一句话 |
| 局限 | 样本、地区、时间、利益相关 |

### 5.3 主张台账

每条进入结论的判断都登记：

| 字段 | 说明 |
|---|---|
| 主张 | 一句话 |
| 依据 | 来源编号 |
| 状态 | 有证据 / 合理推断 / 假设 / 无支撑 |
| 提出者 | |
| 交叉核验者 | 必须不同于提出者 |

### 5.4 候选卡

问题、使用者、决策、所属领域、双删检验结果、最强对手、数据路线、强 AI 对照怎么做、推翻条件。**评分时去掉提出者信息。**

### 5.5 决策日志

每次标准修改、候选淘汰、排序变化都记录：改了什么、依据哪些证据编号、谁提出、你是否确认。

## 6. 审核方式

### 6.1 日常审核（每轮）

Claude 审核每份交回的结果，按问题类型选审核视角，例如：证据是否读过原文、空白判断是否有检索记录、领域覆盖是否均衡、结论是否强于证据。审核意见写入 `04_审核/`。

### 6.2 门槛盲审（P3、P4 结束时）

参照同行评审的做法：

1. 准备一份**不可修改的审稿包**：只含材料本身和评价标准，不含任何人的倾向和已知问题。
2. 交给三位审稿人，**各自在独立的新对话中**审：Claude 的独立子任务、GPT 的新对话、DeepSeek 的新对话。
3. 每份意见写完即**冻结**，冻结前不让审稿人看到其他人的意见。
4. 冻结后再汇总。只有**两位以上独立提出**的问题，才算共识问题。
5. 不为了显得意见多样而改写已冻结的意见。

## 7. 规则

1. **标准先于候选**。每阶段的标准在看候选之前固定；中途修改写入决策日志。
2. **提出者盲评**。所有方向用同一张卡、同一组门槛，评分时不显示来源。
3. **职责分离**。检索方不排序，验证方不选题，审稿方必须引用证据编号。
4. **证据分级**。L0、L1 只能作为线索，不能单独支撑淘汰或入选。
5. **空白判断要有检索记录**。说"没人做过"之前，写出检索词、检索库、命中数；把问题拆成子问题分别检索；只能写"本轮未检索到"，不能写"不存在"。
6. **每个判断都有推翻条件**。写不出推翻条件的判断不进结论。
7. **原始数据先落盘**。任何返回先原样保存，文件名带时间戳，再解析。
8. **基线不能被悄悄改动**。`01_基线/` 里的约束只有你能改，改动写入决策日志。
9. **迭代而不是一次成型**。同一份结果至少经过一次"检索 → 审核 → 补检索"才进入门槛判断。
10. **停止规则**。出现以下任一情况就停下来报告，而不是继续打磨：
    - 同一问题已修订三轮；
    - 连续两轮几乎没有新信息；
    - 关键证据缺失且短期内拿不到；
    - 审稿人之间的分歧无法用证据解决。
    报告内容：当前状态、剩余问题、为什么停、建议的下一步。
11. **允许负结果**。某阶段没有好候选就记录下来，回到上一阶段，不降低标准。
12. **不说空话**。禁止"具有重要意义""填补空白""广阔前景"这类无内容的表述；要写清对哪个机制、方法、决策有什么贡献。
